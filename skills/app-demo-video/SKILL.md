# App Demo Video · 应用介绍视频

## 入口与默认值

- 必须先读取现有素材、产品事实和用户已确认的决定，把本次目标、语言、观众、发布位置、核心任务、版本状态、素材位置和确认记录写入视频项目的 `brief.md`。已有视频必须继续使用原项目；不得为了套流程重做已批准的部分。
- 未指定时，必须采用英文、16:9、60–90 秒的介绍视频；只有用户要求中文或双语时才制作对应版本。时长必须服从内容和自然语速，超出目标区间时先调整台本并交用户审核，不得靠加速配音塞入时长。
- 本 skill 的音色、画面和节奏参数必须作为默认值使用；用户明确更改的项目必须记录在 `brief.md`，并覆盖相应默认值。已给出的决定不得重复询问。
- 必须按下列阶段推进：**先写台本并由用户审核 → 根据批准台本设计动画 → 生成配音 → 试听与片头预览 → 完整制作与检查 → 交付**。没有台本批准记录时，不得生成配音、录制演示或实施动画；只允许查证产品、阅读素材、记录需求和撰写台本。

## 1. 写台本，交用户审核

- 必须完整读取 [references/script.md](references/script.md)，按其台本结构和语言要求起草。
- 必须先核实台本中的功能、界面名称、平台支持和发布状态。不能核实的承诺必须删去或标为待确认，不得让动画代替产品证据。
- 必须提交 `script.md`：观众与核心判断、完整可朗读的旁白、屏幕短文案、各段目的和预估时长；此时只能标画面意图，不得把未审核台本当作最终分镜。结尾必须明确请用户 review 台本，并等待回复。
- 审核版本必须有版本号或内容校验值及用户批准记录。制作双语时，两个版本都必须完成台本审核，不能以英文批准代替中文批准。

## 2. 根据台本定动画

- 必须完整读取 [references/visuals.md](references/visuals.md)，生成 `storyboard.md`，每个镜头必须映射到批准台本的段落 ID。
- 分镜必须逐镜写明：讲什么、屏幕显示什么、从什么状态开始、发生什么动作、以什么状态结束、需要录什么、鼠标是否出现、旁白触发词、入场时长和阅读停留。没有对应叙事目的的装饰动画必须删去。
- 必须先给用户看分镜方案，再进入配音阶段；用户要求先审核动画方案时必须等待批准。未要求独立审核时，可以在同一轮说明方案后继续生成配音，不能把“给出方案”写成“用户已批准”。
- 必须在分镜中分别记录动画入场时间与旁白时间。此时旁白时长只能标为预估；实际音频生成后只调整停留与镜头边界，不得按总旁白长度等比例拉慢整段动画。

## 3. 生成配音

- 必须完整读取 [references/audio.md](references/audio.md)，按已审核语言选择音源，并记录实际模型、音源、语速、发音映射、段落文本和生成参数。
- 必须先生成连续开场段的试听文件，包含叙述、自然停顿和问句，交用户听；新视频或新音源未经试听批准不得混入完整视频。用户明确指定复用已批准音频时，必须复用，不得重新合成。
- 试听批准后必须生成剩余旁白，再以真实音频测量结果更新 `timeline.json` 和分镜的时间，标明各 take、字幕、动作、转场和音乐包络的位置。

## 4. 片头预览与完整制作

- 必须用 Remotion 制作情景动画和合成，按 [references/visuals.md](references/visuals.md) 的功能录制与导出要求执行。必须先导出包含问题、品牌揭示与首个功能镜头衔接的片头预览；用户批准片头或明确要求直接制作全片后才能导出完整版本。
- 必须将媒体、旁白和音乐作为独立素材管理，把字幕和鼠标事件绑定到时间轴，不得把鼠标写进所有镜头的全局覆盖层。执行 JS 项目命令必须使用 pnpm。
- 必须保留素材清单、演示数据版本、字体文件、依赖锁文件和 Remotion 源码，使同一时间轴可以重新渲染。
- 修改已有视频时，必须先标明受影响的镜头、音频与衔接范围。用户要求旁白或音乐不变时必须保持对应素材不变。

## 5. 导出与验收

- 首次完整导出必须覆盖全片检查：解码错误、尺寸帧率与帧数、黑帧或闪帧候选、画面跳动、字幕边界、鼠标落点、语音与动作关系、旁白停顿、音乐衔接和音频峰值。必须逐个查看自动扫描标出的异常候选，并人工看关键操作及转场、听完整混音；命令成功或少量静帧不得作为无异常帧的证明。
- 出现拼块、跳动或闪帧时，必须按 [references/visuals.md](references/visuals.md) 的异常定位方法检查，不得直接认定更换格式或降低并发已经解决。
- 用户限定只检查替换部分时，必须只检查替换区间、两侧衔接及贯穿该区间的音频连续性，并在交付中写明范围；不得声称全片已重验。
- 必须保留 `verification.md`，逐项记录检查方法、结果、异常处理与未验证内容；修复后必须重新验证受影响的项目。

## 6. 交付与发布

- 必须交付 MP4、独立字幕目录中的 SRT、媒体封面以及可继续编辑的项目；交付说明必须给出文件位置、时长、语言、采用的音源和验收范围。默认媒体封面必须采用与视频一致的视觉风格、16:9 构图、app 名称和一句用户收益，缩小后仍可辨认；只有指定其他平台尺寸时才另排版，不得盲目裁切。
- 只有用户要求发布时，才进入 YouTube 或官网发布。采用官网点击播放方案时，必须保留本地封面、点击后才加载播放器；远程托管视频不得再作为大文件提交仓库。发布后的封面和播放入口必须分别核实，不得用上传成功代替页面验证。
- 需要同时写介绍文章或视频说明时，必须按 [references/script.md](references/script.md) 的文字发布结构改写，不得逐字抄录旁白。
